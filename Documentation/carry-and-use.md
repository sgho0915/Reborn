# 5단계 — 소품 운반·사용 기반

## 검토 방법

`Assets/Reborn/Scenes/CarryTest.unity`를 단독으로 열어 Play. 원룸에 저장하지 않은 편집이 있으면 먼저 저장 여부 결정.
기존 RoomBlockout의 가구 배치와 소품은 유지하고 별도 복제 씬에 운반 검증용 봉투와 함 추가.

1. 오른쪽 작은 서랍장 위 연한 종이색 봉투를 E로 조사.
2. **들고 가기** 선택 → 화면 클릭으로 이동 재개.
3. 주방 상판의 주황 함을 조준하면 놓을 수 없다는 안내 표시. E를 눌러도 봉투 유지.
4. 파란 함을 조준해 E → 봉투 배치, 초록 완료 표시 등장.
5. 배치 전 Esc를 누르면 최초 위치로 복구. 화면 클릭 후 다시 집기 가능.

완료 후에는 봉투 재운반 불가. 다시 검증하려면 Play 재시작.
현재 설명·도형·완료 표시는 개발용. 본편 퍼즐 문구나 정답으로 확정한 내용이 아님.

## 규칙과 구현

- Explore → Inspect → Carry → Explore 문맥 구성.
- 한 번에 하나의 소품만 운반. 고정 소품은 들고 가기 버튼 없음.
- 들고 있는 동안 원본 모델을 카메라 아래쪽으로 이동하며 충돌체만 임시 비활성화. 소품 복제 없음.
- 조사 화면에서 집기 직전 거리·가림 조건 재확인.
- 사용 직전 첫 충돌 표면을 재검사하여 벽 너머·2m 밖 사용 거절.
- `ItemPlacementTarget`은 허용 stableId와 빈 슬롯 여부를 검사. 부적합 대상에는 소품 유지.
- 위치 상태를 Home / Held / Placed로 관리. 슬롯 점유를 기준으로 완료 표시. 애니메이션 완료에 의존하지 않음.
- 취소 시 최초 부모·월드 위치·회전·크기·충돌체 활성 상태 복원.
- 운반 컨트롤러 비활성화 또는 소품/대상 비활성화 시 복구. 배치된 소품 복구 시 슬롯 완료 해제.
- 앱 전환으로 커서가 풀려도 소품 유지. 화면 클릭으로 재개.

`CarryableObject`는 Rigidbody 없는 정적 소품용. 물리로 던지기, 대형 물체, 손 애니메이션, 벽 관통을 막는 전용 운반 렌더링은 미구현.
저장·씬 간 소유권 이전은 미구현. 테스트 씬을 종료하면 초기 상태로 재시작.

## 퍼즐 연결 범위

기획 `../../docs/development/08-production-inventory.md`에 따라 번호표·호출판 제작 보류 유지.
본편 대기실 P01은 최신 컨셉에 맞춘 정답·회수 조건 확정이 필요. 이번에는 봉투 ID 일치 → 배치 → 완료 상태 변경의 공통 기반만 검증.
본편 퍼즐을 구현할 때 운반 상태를 전체 GameState 및 SaveService와 통합해야 함.

## 검증

Unity 6000.6.0f1 Play 모드에서 `Reborn.Editor.CarryValidation.Run()` 실행:

- 조사에서 집기, 탐색 잠금 해제, 단일 소유권 확인.
- 잘못된 함·사거리 밖·장애물 뒤 사용 거절.
- 취소 후 위치·크기·충돌 복구 및 재집기.
- 정상 배치와 완료 반영, 중복 적용 거절.
- 대상/컨트롤러 비활성화 시 복구.

별도 실시간 검사로 운반 중 60프레임/1초 이동 약 1.600m 확인.
기존 `InteractionValidation.Run()`의 조사·가림·입력 잠금 회귀 검사 통과.
실제 E/Esc/버튼 조작 체감은 사용자 확인 대기. 플랫폼 배포 및 저장 복원 검증은 미실시.
